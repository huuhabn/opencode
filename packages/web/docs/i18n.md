# Internationalization

Paths in this guide are relative to `apps/web`. The app is Vite + React and uses `i18next` with `react-i18next`. Do not use `next-intl`, `useTranslations`, `getTranslations`, or a `messages/` directory.

`src/main.tsx` waits for `i18nReady` before the first render. `setLocale` from `@/i18n` writes the `locale` cookie, sets `html.lang` and `html.dir`, then calls `i18n.changeLanguage`.

## Locales

The list is `languages` in `src/i18n/languages.ts`. `defaultLocale` is `en-US` (`src/i18n/locale.ts`). The cookie name is `locale`. Unknown values, including the legacy codes `en_US`, `ja_JP`, and `zh_Hans`, normalize through `normalizeLocale`.

`fallbackLng` is `en-US`. `load` is `currentOnly`, so only the active locale is fetched.

Supported values:

`en-US`, `zh-Hans`, `zh-Hant`, `pt-BR`, `es-ES`, `fr-FR`, `de-DE`, `ja-JP`, `ko-KR`, `lo-LA`, `ru-RU`, `it-IT`, `th-TH`, `uk-UA`, `vi-VN`, `ro-RO`, `pl-PL`, `hi-IN`, `tr-TR`, `fa-IR`, `sl-SI`, `id-ID`, `nl-NL`, `ar-TN`, `az-AZ`.

`ar-TN` and `fa-IR` are RTL. See `text-direction-ltr.md`.

The header switcher is `src/components/language-switcher.tsx`. `/settings/appearance` has its own searchable list and also calls `setLocale`.

## Files

Copy lives in flat JSON:

```text
src/i18n/locales/{locale}/{namespace}.json
```

Each locale has a loader at `src/i18n/locale-resources/{locale}.ts`. `src/i18n/load-resource.ts` loads that module with `import.meta.glob`, then dynamic-imports the namespace file. A missing file rejects, and i18next falls back to `en-US`.

`keySeparator` is `false`. A key such as `billing.title` is one flat string, not a nested object. Interpolation uses i18next placeholders, for example `{{name}}`, not ICU `{name}`.

`defaultNS` is `platform`. These namespaces load before the first paint (`initialNamespaces` in `src/i18n/client.ts`):

| Namespace | Used for |
| --- | --- |
| `platform` | Shell labels, settings, workspaces, billing. Default namespace. |
| `common` | Shared actions and the header language label (`language.displayLanguage`). |
| `layout` | Sidebar collapse and expand labels. |
| `navigation` | Loaded up front. Sidebar titles currently go through `platform`. |

Other JSON files under `locales/` load the first time a component calls `useTranslation` with that namespace. `useSuspense` is `false`.

## Using translations

```tsx
import { useTranslation } from 'react-i18next'

export function BillingHeader({ name }: { name: string }) {
  const { t } = useTranslation('platform')

  return <h1>{t('billing.title', { name })}</h1>
}
```

`platform.json`:

```json
{
  "billing.title": "Billing for {{name}}"
}
```

Navigation titles are the English string used as the key. `nav-group.tsx` and `command-menu.tsx` call `t(title, { defaultValue: title })`, so a missing translation still shows English.

There are no server components. Do not add `'use client'`.

## Adding a string

1. Add the key to `src/i18n/locales/en-US/{namespace}.json`.
2. Add the same key to every locale you are translating. A missing key in a loaded file renders the key. A missing file falls back to `en-US`.
3. If the namespace is not one of `common`, `layout`, `navigation`, or `platform`, either pass it to `useTranslation('namespace')` or add it to `initialNamespaces` when it must exist before paint.
4. A new locale needs an entry in `languages`, a folder under `locales/`, and a `locale-resources/{locale}.ts` loader. RTL locales also need to be added to `rtlLocales` in `src/i18n/locale.ts`.

Keep filter, sort, and status state as stable ids. Translate only the label shown to the user.
